# 组件目录

每个格子放一个组件（`element.type`）。组件会按格子大小自动缩放字号：先用大字号，放不下再缩小，正文最小 12px。超出容量时脚本报错，需要拆格或拆页，不要硬塞。

## 一、卡片样式（格子外观）

格子在"纯卡片""线卡混用"页里画成卡片时，用 `card` 指定样式；不写时用默认的浅底卡。

| `card` | 样子 | 适合 |
|---|---|---|
| `plain`（默认） | 浅色底（或白底）＋近乎看不出的描边＋柔阴影 | 大多数格子 |
| `header` | 顶部主色实心表头条（白字），下面浅底或白底 | 格内内容较多、需要醒目小标题的分组 |
| `dark` | 主色渐变深底、白字（等同 `fill: "重点"`） | 结论、判断；每页最多 1 个 |
| `number` | 白卡左上角压一个主色编号圆点 | 横向流程、步骤卡；卡与卡之间自动加箭头 |
| `label` | 左侧一块主色深色块写阶段名，右侧放内容 | "阶段 → 事项"，通栏横条 |

页面内卡片圆角由整套设置决定，见 [视觉规范](visual.md)。

## 二、文字类组件

| `type` | 内容 | 参数 | 容量与最小格子 |
|---|---|---|---|
| `statement` | 一句结论，可带一行补充 | `text`，`sub`，`size` | 结论 ≤ 40 字；宽 ≥ 260 |
| `points` | 要点列表：编号或图标＋粗体导语＋灰色说明 | `items: [[导语, 说明, 图标?], …]` | ≤ 4 条长要点；每条宽 ≥ 280 |
| `para` | 一句加粗导语＋一段正文 | `lead`，`body` | 正文 ≤ 120 字；宽 ≥ 300 |
| `feature` | 图标卡：大图标＋标题＋一段正文 | `icon`，`title`，`body` | 正文 ≤ 70 字；宽 ≥ 200、高 ≥ 200；用于 3～6 个并列格 |
| `tags` | 标签胶囊：一排圆角小标签 | `items: [文字, …]`，`lead`（可选） | 3～8 个，每个 ≤ 6 字 |
| `tip` | 提示条：警示或信息图标＋一行强调色文字 | `text`，`kind: warn/info` | 一行，≤ 36 字；放在格子底部收尾 |
| `split_note` | 卡内上下分区：上面要点，细线下面一段浅灰补充 | `main`（任一组件），`note` | 补充 ≤ 60 字；补充写事实或下一步，不写口径、来源（进页脚） |

## 三、关系图示（格内小逻辑）

| `type` | 表达的关系 | 参数 | 容量 |
|---|---|---|---|
| `steps` | 递进、流程（节点＋箭头，可带图标与说明） | `items: [[节点名, 说明?, 图标?], …]` | 2～5 个节点 |
| `chain` | 因果：对象 → 现象 → 判断 | `rows: [[对象, 现象, 判断], …]` | 1～3 行 |
| `compare` | 占比对比细条 | `rows: [[名称, 文本值, 数值], …]`，`note` | 2～4 行 |
| `icon_steps` | 图标方块＋标题＋短说明，箭头横向相连 | `items: [[标题, 说明, 图标], …]` | 3～5 个 |
| `num_pair` | 两个大数字，中间竖线隔开，各配一句说明，下面可接一句注释（不加横线） | `items: [[数值, 单位, 说明], …]`，`note` | 2～3 个数字；`note` 写判断或补充事实，口径、来源写进页脚 |
| `stack` | 格内上下叠放多个组件（如结论句＋关系图示） | `items: [[组件, 权重], …]` | 2～3 个 |

## 四、数据类组件

| `type` | 用途 | 参数 | 最小格子 |
|---|---|---|---|
| `kpi_row` | 一排关键数字（数字＋单位＋说明） | `items: [[数值, 单位, 说明], …]` | 2～5 个；高 ≥ 130 |
| `table` | 表格（表头整行连续渐变，可高亮一行） | `header`，`rows`，`colw`，`hl` | 行列 ≤ 7×6；高 ≥ 220 |
| `bar_h` | 横向条形图，可标重点条；按条数取高（每条约 44px），不拉满格子 | `cats`，`vals`，`hot`，`suffix` | 3～8 条；格子比图高出很多时报错，收格并在空处放图 |
| `column` | 竖向柱形图，适合按时间或少量类别比较；可标重点柱（重点主色、其余灰），柱宽约 46px 以内 | `cats`，`vals`，`hot`，`suffix`，`decimals` | 3～10 根；类别名短（季度、年份、片区） |
| `line` | 折线图，看趋势；第一条线为重点（主色、实线），对比线为灰（第二条虚线）；单线点数 ≤8 时逐点标数，多线只标末端；纵轴不必从 0 起，自动取略低于最小值的整数档 | `cats`，`series`（`[{"name": "2025 年", "vals": [...]}, …]`，单线也可直接写 `vals`），`hot`（重点点序号），`suffix`，`decimals`，`min`/`max` | 4～12 个点，最多 3 条线；时间序列优先用折线，类别对比用柱形或条形 |
| `donut` | 环形占比图，中心写总量 | `cats`，`vals`，`center` | 2～6 项 |
| `bar_cards` | 带进度条的分项行 | `rows` | 3～6 行 |

> 瀑布图 `waterfall` 暂停使用，规格检查会报错。增减拆分（收入增量来自哪些品类、利润变动由哪些因素构成）各项都为正时用 `bar_h`，按贡献从大到小排序，起止合计写进标题或 `kpi_row`；只要有一项为负（减少、拖累），用 `table` 列出正负项。`bar_h` 和 `column` 的数值轴从 0 起，含负值时规格检查会报错。

## 五、图片

| `type` | 用途 | 参数 |
|---|---|---|
| `photo` | 图片格：按格子比例裁切，自动降饱和、向主色调色；留在正文区内，不越过内容区边界、不贴页边 | `topic`（图库文件名、本机图片路径，或中文关键词，多个用顿号隔开），`anchor`，`bleed`（默认 `false`；写 `true` 才把贴正文区边缘的一侧铺到页边）。图上不加文字说明 |

**什么时候加图**：正文页默认不放图。出现下面任一情况时考虑加一个图片格：

- 本页材料确实少，收格、换紧凑组件、与相邻页合并之后仍有空；
- 生成后的留白检查（`build.py` 渲染后自动运行，见 [成稿与预览](visual-check.md)）提示本页空块多；
- 条形图、表格按内容取高后，格子里空出一块（规格检查要求收格，空出的位置正好放图）；
- 分隔线被内容截短、旁边格子留空大（生成时会提醒）。

**硬性检查**（不满足时生成失败，必须改 `deck.json` 重跑）：

- 渲染后整页空白超过正文区 20% 且没有图片格的页，留白检查报错：先收格、换紧凑组件或并页把空白降下来，内容确实只有这些时加图片格。
- 图片格没取到图（留下一块空）也报错：换中英文关键词或写本机图片路径重跑；确实没有相关的图，就去掉这一格并收格。

先压缩版面，再考虑加图；不要用图片顶替本该写出来的论据。

**放在哪里**：图片格**至少挨着正文区的一个角**——左右必须有一边贴正文区边缘，上下也必须有一边贴边（例如右侧整栏、右下角、左上角）。不要把图片夹在两张卡片中间或悬在页面中央。规格检查会拦下不挨角的图片格。图片只能单独占一格，不放进 `stack`、`split_note`。

**选哪张图**：图要和本页内容相关，没有相关的图就不放。

- 先用 `python3 scripts/photos.py 搜索 关键词` 查自带图库：每张图都有人工看过的中文画面描述和匹配词，按单张图打分，不按大类轮流取；
- 可以直接写文件名（如 `"topic": "office-05.jpg"`）或本机图片路径；
- 标了"不自动用"的图有明确地点或标识（外国地标、车体字样），只在按文件名指定时使用，并且只作背景；
- 联网取图默认打开：自带图库没有强相关的图时到开源图库检索（见 [素材与版权](assets.md)）。`topic` 中英文一起写（如 `"运维工程师、engineer inspecting battery"`），检索更准；离线时关键词找不到图，规格检查报错。

正文页每页最多 1 个图片格，面积不超过正文区的 1/3。封面、转场页的全幅图由整稿模板处理，同样按关键词或文件名取图，取不到就不放。图片来源与授权见 [素材与版权](assets.md)。

## 六、图标

`points`、`steps`、`feature`、`icon_steps`、`tip` 可带图标。**`points` 默认每条都配图标**（第三项），只有编号顺序本身有意义时才不配；整稿过半要点列表没有图标时规格检查会提醒。写 IconPark 英文名（如 `trending-up`）或中文关键词（如"风险""仓储""复测"），名字写错或词表里没有时，脚本先按英文名前缀、词段近似匹配（如 `building` → `building-one`），仍找不到用通用图标，规格检查会提醒换个贴切的名字。图标跟随主色，不使用模板残留的颜色。

## 七、选组件的顺序

1. 先看这一格的论据是什么关系：并列、递进、因果、对比、构成、趋势。
2. 有数字且能比较 → 数据类；没有数字 → 文字类或关系图示。
3. 文字多的页，优先用 `feature`、`para`、`points` 配一个关系图示，避免整页只有段落。
4. 同一页不要出现两个同类关系图示；整稿内同一组件连续使用不超过 3 页。
5. 不要每页都是"左边图表、右边一列要点"。右侧那格可以是结论卡（`statement`）、`split_note`、`num_pair`、`chain`、`compare`，或横切成"数字＋结论"两层。
6. 表格按内容高度画、贴格子顶部，不再拉伸填满；格子明显比表格高时，收格，把下方空间给指标带、结论条或关系图示。
7. 整页只有文字（全是 `points` / `para`，没有图标、关系图示、数字或深色卡）会被规格检查拦下。
