# 工作汇报：故事线骨架与每页写法

## 由执行本技能的大模型读材料并作判断

从原文明确听众要了解或决定什么，比较关键变化、相互制约的事实以及尚缺的依据。写出全篇主判断，并解释各章为什么按这个顺序展开。若几组数字看似矛盾，先核对期间、分母和统计对象，再决定能写到什么程度。

将形成的一条大纲交给用户。用户改动某一判断后，用确认稿更新对应页的证据与计划。Python 可用于提取表格、核算金额、检查来源字段和容量；主判断、因果解释、材料取舍和章节顺序由当前大模型依据原文完成。

## 总原则

- 确认一条故事线。先写全篇主判断与每章要证明的问题，按 outline-template.md 展开到**中观点的论据**；确认后用选择框确认配色，再把论据补成底稿（口径、比较基准、出处）。观点或论据不全、且可由公开信息补足时，由大模型联网检索自行补充并标明「公开信息」及来源、日期；本单位内部数据不检索，列入补充材料清单。
- **故事线写到论据层**：页标题之下共两级。每个页内中观点下面写 2 条左右论据要点（数字、原因、事实），放在确认表的“中观点论据”一列，让用户在确认故事线时就能看到每个判断靠什么撑住。底稿再把这些论据补齐口径与出处，由 deck.json 分配给格子和组件。
- **结论先行**：第 3 页就给出整体判断，后面各章是对它的展开与论证，最后落到问题、举措和监测。
- **每页一个结论**：标题是这一页要让听众记住的那句话；主体是支撑它的数字和要点；结论带是收束或延伸的一句判断。
- **章节 3–6 个**：目录每章只列章名和一句陈述式说明。成稿总结后追加致谢。

## 骨架一：经营分析（年报 / 半年报 / 季度经营分析）

下表只定页面功能，不定骨架和图示。排版时由模型按材料关系选择区隔方式、切分和组件，写入 [deck.json](../../references/deck-json.md)。

| 页 | 章节 | 作用 | 页面功能 |
|---|---|---|---|
| 1 | — | 封面：标题 + 一句话副标题（总体判断） | （封面，不绑定） |
| 2 | 目录 | 3–6 章，每章一句说明 | （目录，不绑定） |
| 3 | 经营概览 | 核心结论：一个最关键的数 + 一句判断 | 核心观点 |
| 4 | 经营概览 | 主要指标，或经营环境的有利 / 不利因素 | 一组核心指标，或对比 |
| 5 | 经营概览 | 财务摘要：关键指标多期对比 | 趋势 |
| 6–8 | 利润（收支）分析 | 利润形成、变动拆解、主要影响因素 | 趋势、并列 |
| 9–14 | 业务与市场 | 分产品 / 分板块 / 渠道 / 地区，每个板块一页 | 完成率、分类定位、转化、流程、并列 |
| 15–16 | 财务与能力 | 资产负债与现金流、能力建设 | 趋势、循环、层级 |
| 17 | 关注与展望 | 需关注的问题（4–6 个） | 并列 |
| 18 | 关注与展望 | 下阶段工作重点（3–4 项） | 层级 |
| 19 | 关注与展望 | 建议监测指标（4–6 个） | 完成率 |

骨架一不是固定页序：章节可以按材料改为“按问题展开”（结论 → 三个问题 → 每个问题的原因与对策）或“按目标对照”（目标 → 完成情况 → 差距 → 措施），页数和顺序以材料为准。页面功能跟着内容改，分区跟随材料关系与分量，选用可容纳完整论据的图示。

## 骨架二：项目进展汇报

封面 → 目录 → 项目总体进展（一组核心指标，里程碑用时间进程）→ 已完成工作（并列或流程）→ 关键成果与数据（趋势）→ 存在问题与原因（对比）→ 下一步计划（流程或时间进程）→ 需协调事项（并列）。

## 骨架三：年度工作总结 / 述职

封面 → 目录 → 全年工作概况（一组核心指标）→ 重点工作 × 3–5（每项一页：并列；做了什么、结果数字、经验写进该变体的图示）→ 不足与反思（对比）→ 明年思路与目标（层级）→ 具体举措与时间安排（流程或时间进程）。

## 骨架四：专题调研 / 问题分析

封面 → 目录 → 结论摘要（核心观点）→ 背景与现状（趋势）→ 问题表现（并列）→ 原因分析（层级或对比）→ 对标与借鉴（对比或分类定位）→ 对策建议（层级）→ 实施路径（流程）。

## 每页写法

- **标题**：写可用本页证据检验的判断，交代数值变化的意义。例如“冷饮新品扩大收入增量，液体乳仍决定基本盘”。
- **小标题（卡片 / 模块标题）**：写一句可被证据支持或推翻的判断，例如“销售回款提速改善了经营现金流”。图例、轴名与单位可以用名词。
- **要点**：每条 = 页内中观点（加粗，≤20 字）+ 一行支撑点（数字、原因或依据）。一张卡 2–3 条。只有中观点、没有支撑句，这一页不算写完。
- **指标**：数值 + 单位 + 标签（+ 比较）；如 `("643.31亿", "营业收入", "▲ 4.13%")`。
- **结论带**：增加一条标题尚未表达的影响、条件或待验证的问题，复核标题与结论带是否同义；可带 1–2 个最关键的数字胶囊。
- **来源**：每个内容页都写，精确到页码；属于自己测算或判断的写明“整理者测算”“属分析判断”。
- 派生数字（差额、占比、剔除后增速）自己先用代码算一遍再写上，并在来源中注明“整理者测算”。

经营分析第 3 个物理页放一个关键数与一句总判断，章节转场安排在它之后（将总判断作为 deck.json 正文首页，按[整稿页序](../../references/report-structure.md)生成）。将同一原因的起点、传导和后续验证串起来。若材料能解释利润或现金的反向变动，统一口径做桥接，标明计算的剩余项。末章列监测对象、基线和下一期判断方法。

支撑行优先写底稿的比较、原因与影响，把口径放在来源行或脚注。容量不足时先扩大区域、减少分区或拆页，再完整渲染复核。每个正文页剔除标题、来源、页码后至少 160 字，同时检查主体留白。
