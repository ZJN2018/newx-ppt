# 第二轮材料清单

故事线和配色确认之后，先写 `evidence.md` 论据底稿，再由 `check_evidence.py --checklist materials.md` 生成此清单，写 `deck.json` 之前发给用户，并调出选择框：① 我来补充 ② 不补，按现有材料成稿 ③ 你定。逐条列出中观点缺的数字、案例、口径和出处。不要编造。可由公开信息补足的观点和论据，已在写大纲时由大模型联网检索补上（标「公开信息」及来源、日期），本清单只列单位内部才有的缺口；不要为了填空去调用付费搜索。

确认过的大纲已写到中观点论据要点。底稿把这些论据补齐口径、比较基准和出处，再列这张清单；清单写明缺哪条论据、哪项口径或出处，不必重复完整底稿。用户补充后更新底稿，重新检查每中观点至少2条论据且至少1条带口径和比较基准的数字论据，每页至少2个中观点、4条论据及160字正文。

用户补完，或明确说先用现有材料（「你定」或「不需要」）之后，更新底稿并检查。材料不足的页依次考虑与相邻同主题页合并、降为相邻页区域、补材料；底稿通过后逐页排版，写 `deck.json`。仍缺什么，继续记在本清单，不得用空框、大色块或放大字号凑满。写成稿时只采用已核实的事实和有依据的判断。例如已知期末客均合同数，却没有同口径上期数，就只写期末水平，不判断复购是否改善。用户明确要求看缺口时，才在相应页面标注。

| 序号 | 故事线位置 | 缺什么 | 用在哪一页的哪个中标题 | 已有材料 | 请补充 |
|---|---|---|---|---|---|
| 1 | （部分 / 页标题观点） | 数字、案例或出处 | （页内中标题或中观点） | 没有，或口径对不上 |  |
| 2 |  |  |  |  |  |

结束页要列汇报人（`settings.reporter`）。材料里没写汇报人时，在这张清单末尾加一行问用户；用户不补就列单位，不要编造姓名。

清单末尾加一行：「如有现场照片、产品图、LOGO、荣誉证书等图片，也可一并发来，优先用在封面、转场和相关正文页。」

没有缺口时也发这一张表，并写「现有材料已覆盖这条故事线，没有待补项」。用户确认之后再写稿。

用户回复不补材料时，合并或删减无支撑观点，底稿检查通过后成稿。用户尚未回复时停在材料询问。
