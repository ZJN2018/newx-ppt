# 工作汇报流程

适用于部门总结、经营分析、项目进展、述职与专题汇报。用户要确认三项：故事线、配色、补充材料。**三项放进同一个选择框一次问完**，不要分三轮：有选择题工具（AskUserQuestion、ask_user_input 等）就一次调出一个含多道题的选择框，每题推荐项放第一个并标“推荐”，另留“你定”，用户要改的写在“其他”里；工具一次只能问一题时，改成一条文字消息列出全部题目和编号，让用户一次回复（如“1①2②3②”）。以下脚本均在工作区运行，路径以技能根目录为基准。每个案例单独保存确认状态、输入和台账。

## 读材料

用 `scripts/ledger.py show` 看最近几套的配色和区隔方式，新稿避免雷同。读完原文，在 notes.md 记录关键数字的口径、比较基准、单位和出处，以及材料能支撑的判断。写作见 [书面语规则](writing.md)。

## 准备（1）故事线

按 [故事线](storyline.md) 和 [模板](outline-template.md) 写一条大纲，包含部分、页标题观点、主要内容、页内中标题或中观点、**中观点论据**（每个中观点下 2 条左右论据要点，带关键数字；口径和出处留到底稿）。大纲先不单独发给用户，写完论据底稿和材料清单后，和配色、补充材料一起在[一次确认](#一次确认三项)里问。

**缺的用公开信息自己补**：写大纲时，页标题观点、页内中观点或中观点论据不全，而缺的部分属于可公开查到的信息（行业数据与排名、政策文件、标准规范、公开报道、上市公司公告、宏观统计等），由大模型自己联网检索补上，不必先问用户。补进来的论据标「公开信息」，写明来源网站或文件名、发布日期，和单位自己的材料分开写；查不到或对不上的不写。单位内部数据（本单位的业绩、人员、项目进展等）网上查不到，仍列入补充材料清单问用户，不得用相近公开数据顶替。没有联网检索工具时跳过这一步，照旧列缺口。

**写完大纲就开始预取图片**：封面和各章转场要什么图此时已经清楚，后台运行 `python3 scripts/photos.py 预取 --out out "主题1、english words" "主题2、english words" …`，等用户确认的时间里图就下好了，生成时直接命中缓存。

## 准备（2）论据底稿（-2 层）

紧接大纲，逐页把每个中观点的论据要点写进 `evidence.md`，补上口径、比较基准和出处。每个 -1 层中观点至少 2 条 -2 层论据，其中至少 1 条有数字，正文须同时交代口径和比较基准。每条写材料名及页码或章节；派生数据标“整理者测算”并写明算法。缺少的事实写进对应中观点的 `gaps`，不能编造，不能只填口径字段却不写实际论据。

底稿在一个 `evidence-json` 围栏中保存 `pages`，每页含 `page`、`section`、`title`、`midpoints`。每个中观点含 `title`、`evidence`，论据含 `text`、`source.material` 和 `source.locator`；数字论据再填 `numeric.scope`、`numeric.comparison`，两项直接引用正文中的口径和比较基准文字，保证机器输入与读者看到的论据一致。派生论据填 `derived.label="整理者测算"` 与 `derived.formula`。底稿完整示例见下文。

```bash
python3 scripts/check_evidence.py evidence.md --checklist materials.md --json evidence-check.json
```

检查每个内容页至少 2 个中观点、合计至少 4 条论据、论据正文去空白后不少于 160 字；标题、出处及口径元数据不计字数。封面、目录、致谢不套内容页门槛。脚本退出码 1 表示需要修改底稿，2 表示格式错误。

未满足的页按此顺序处理：**先考虑与相邻同主题页合并 → 再考虑降为相邻页内的一个区域 → 仍缺材料的列入补材料清单**。脚本给出候选相邻页与逐中观点缺口，由执行者判断主题是否适合合并；不要为保页数补空框、大色块、重复文字或放大字号。

### 由底稿生成材料清单

按 `materials-checklist.md` 的问法整理 `materials.md`，逐条保留页面、中观点和需要补的数字、案例、口径或出处。只列真实缺口。

## 先找 LOGO

汇报对象是公司、银行、医院、学校等有 LOGO 的单位时，确认前先把 LOGO 找到，配色和版面都要用它。按顺序找，找到即停：

1. 用户给的 LOGO 图片。
2. 源材料里的 LOGO：年报、半年报、公司介绍的封面和前几页通常有一张干净的 LOGO 图。

   ```sh
   python3 scripts/logo.py find 源材料.pdf [更多 PDF 或图片] --out logo-candidates
   ```

   逐张看候选图，确认是汇报对象本单位的 LOGO（不是子公司、合作方、审计机构），选一张。
3. 联网找该单位官方 LOGO（官网、百科页面），下载到本机。

找到后：`confirm.py ask` 用 `--logo` 算推荐色系；路径写进 `deck.json` 的 `settings.logo`，脚本自动放到封面、目录、转场、结束页右上角和正文页眉右上角。三处都没有，或用户说不放，才不放 LOGO，并在 `materials.md` 里写明原因。

## 一次确认三项

大纲、底稿和材料清单都写好后，先算推荐色系（有 LOGO 用 LOGO，有主色值用主色值，否则按行业，都没有用藏蓝；规则见 [配色](../../references/palette.md)），再列出三道题：

```sh
python3 scripts/confirm.py ask --outline 故事线.md --checklist materials.md --industry 医疗   # 或 --logo logo.png / --color C8102E
```

同一条消息里给出大纲全文和材料缺口清单，然后调出**一个**选择框，按脚本输出放三道题：

1. 故事线：① 确认这条故事线（推荐）② 我要修改 ③ 你定
2. 配色：推荐色系（标“推荐”）、2 个备选、你定；每项写色系名和主色色值，不让用户自己输入色值
3. 补充材料：① 我来补充（文字或图片）② 不补，按现有材料成稿 ③ 你定（没有缺口时把②标“推荐”）

用户选完一次记录：

```sh
python3 scripts/confirm.py answer --outline 故事线.md --checklist materials.md \
        --storyline 确认 --palette 科技蓝 --materials 不补
```

- 故事线选“我要修改”：配色照记，按意见改大纲、同步改底稿和清单，再运行 `confirm.py ask`，只重问故事线和补充材料两题。
- 补充材料选“我来补充”：等材料到了纳入底稿、通过检查，再运行 `confirm.py materials --choice 已补充 --checklist materials.md`。
- 把 `confirm.py` 记录的色系名或 LOGO 原色值（如 `#E30613`）写进 `deck.json` 的 `settings.preset`；圆角 / 直角整稿统一，写进 `settings.corner`。
- 单项命令 `confirm.py storyline / palette / materials` 仍可用，只在重问单项时用。

**补充材料可以是图片**：单位 LOGO、现场照片、产品图、活动或团队合影、荣誉证书、项目效果图等。用户给的图片优先于图库和联网取图：按内容放到封面、转场或相关正文页的图片格（`topic` 直接写本机图片路径），在 `materials.md` 里记下每张图用在哪一页。用户图片同样按 [视觉规范](../../references/visual.md) 调色、裁切，不在图上加文字说明；LOGO 写进 `settings.logo`（本机图片路径），脚本自动放到封面、目录、转场、结束页右上角和正文页眉右上角：白底、黑底自动抠成透明，浅色背景放原色，深色、主色或照片背景换纯白反白版，色块标（如黄底方标）原样放。

用户补完后同步更新 `evidence.md`，再运行检查。没有缺口也说明已有材料已覆盖。

用户把缺口补上，或确认没有缺口之后，这一步才算通过。更新后的论据底稿必须通过 `check_evidence.py`；没有回复或仍未通过时不要写 `deck.json`。用户不补时，合并或删减无支撑观点，重新检查通过后排版。

### 一页完整示例：中观点 → 论据 → 区域与画法

以下为虚构公司示例，数字只用于展示底稿格式，不能用于真实成稿。`evidence.md` 内容：

```evidence-json
{
  "pages": [{
    "page": 3,
    "section": "经营概览",
    "title": "收入保持增长，费用增速低于收入增速",
    "midpoints": [{
      "title": "主营业务收入保持增长",
      "evidence": [{
        "text": "报告期合并口径营业收入为120亿元，较上年同期增长5%；比较基准为上年同期，统计范围包含本期纳入合并报表的各业务主体，金额单位为亿元。",
        "source": {"material": "示例公司半年报", "locator": "第3页"},
        "numeric": {"scope": "报告期合并口径营业收入", "comparison": "比较基准为上年同期"}
      }, {
        "text": "报告的经营讨论将收入变化与主营产品销售联系起来，并分别披露分部收入和成本；本页据此说明收入变化的业务背景，不将披露的同期变化进一步解释为未证实的因果关系。",
        "source": {"material": "示例公司半年报", "locator": "经营讨论章节"}
      }]
    }, {
      "title": "期间费用增速低于收入增速",
      "evidence": [{
        "text": "报告期合并口径期间费用为18亿元，较上年同期增长2%；统计项目包括销售、管理、研发及财务费用，比较基准为上年同期，金额单位为亿元，与营业收入采用相同合并范围。",
        "source": {"material": "示例公司半年报", "locator": "第18页"},
        "numeric": {"scope": "报告期合并口径期间费用", "comparison": "比较基准为上年同期"}
      }, {
        "text": "整理者测算：本期期间费用率为15%，口径为期间费用除以营业收入；比较基准为本期合并报表水平，不作同比。该指标用于描述费用与收入的配比，不能据此单独判断各项费用投入是否充分。",
        "source": {"material": "示例公司半年报", "locator": "第3页及第18页"},
        "numeric": {"scope": "口径为期间费用除以营业收入", "comparison": "比较基准为本期合并报表水平，不作同比"},
        "derived": {"label": "整理者测算", "formula": "期间费用率=18÷120×100%=15%"}
      }]
    }]
  }]
}
```

运行前述命令后，这页为 2 个中观点、4 条论据，正文超过 160 字。格子一承载“收入保持增长”的 2 条论据，格子二承载“费用增速低于收入”的 2 条论据；保留各自完整口径与出处。排版时按两组论据的关系选切法和组件：例如上面一排 `kpi_row` 放收入与费用两个数字，下面左格用 `compare` 比增速、右格用深色 `statement` 写结论；或者一张卡里放 `split_note`。底稿里的"口径""比较基准""出处"写进页脚或格内注释，不要用"核查依据"之类的词当小标题印到页面上。


## 逐页排版：写 deck.json

先按[整稿页序](../../references/report-structure.md)排好章节和正文页，再**逐页**决定（每页单独写，不用循环或模板函数批量生成；规格检查会拦下整稿版面单一的稿子）：

1. **区隔方式**：纯卡片、纯线条、线卡混用、创意型（少用）。整稿内交替使用，相邻页不同构。
2. **切分树**：按本页论据的关系和分量切 2–8 格，主证据最大。一格不必对应一个中观点，辅证据、关键数字、结论可以各占小格；整稿要有切得细的页（4 格以上、5 格以上），要有整块放大主证据的大主块页，第一刀也要有变化，不要通篇左右两分，也不要通篇田字格。常用骨架、格子尺寸与容量见 [版面切分规格](../../references/split.md)。
3. **每格的组件与卡片样式**：文字类、关系图示、数据图表、图片、图标，参数与容量见 [组件目录](../../references/components.md)。文字多的格子优先用卡内小逻辑（`split_note`、`num_pair`、`icon_steps`、`tags`、`tip`），不堆段落。
4. **图片**：封面、每章转场和正文图片格的 `topic` 各写**一次**中英文关键词（如 `"候诊区、hospital waiting room"`），由脚本按元数据自动挑图；**不要自己逐张搜索、打开候选图挑选，也不要把图库原文件名当检索词**。生成后看总览，只把明显不相关的图换一次关键词重跑。没有相关的图就不放，并在交付说明里写明。正文页在内容少或留白检查提示空块多时考虑加图：每页最多一格，不超过正文区 1/3，**至少挨着正文区一角**，只放与本页相关的图；自动降饱和并向主色调色。详见 [组件目录·图片](../../references/components.md)，版权提示见 [素材与版权](../../references/assets.md)。

整稿字段见 [deck.json 格式](../../references/deck-json.md)。所有数字取自 `evidence.md`，格子用 `evidence` 字段引用论据编号。

## 成稿、预览与交付

```sh
python3 scripts/build.py deck.json --out out/ --evidence evidence.md
```

脚本先跑规格检查（格数、最小尺寸、容量、深色卡数量、区隔方式约束、数字是否出自底稿、相邻页雷同），有错误就停，改 `deck.json` 后重跑。通过后生成 PPTX、PDF、逐页 PNG 和总览图，并按逐页 PNG 量每个格子的实际空块（结果写入 `<名>-留白检查.json`）。逐条处理留白提醒：先收格、换紧凑组件或并页，仍空的加挨角的图片格。**以下两种是硬性错误**（生成返回失败，必须改完重跑）：整页空白超过正文区 20% 且没有图片格；图片格没取到图。详见 [组件目录·图片](../../references/components.md)。看总览和单页，按 [预览](../../references/visual-check.md) 和 [细节](../../references/details.md) 检查；最多三轮视觉修订，记录余项。交付可编辑 PPTX、PDF、总览图，并说明配色依据、推算口径、代选内容和无法验证的项目；用了联网图片时附 `图片来源.json`，并把生成时打印的版权提醒转告用户。

## 用户不在或说「你定」

已有用户选择用上述命令记录。其余用 `confirm.py defaults --reason 用户不在 --industry 行业 --outline 故事线.md` 补齐（配色按行业指定）；用户事先说过不补材料时加 `--materials 不补充`。没有材料答复的“用户不在”停在材料确认；「你定」可按已有材料收束。代选也要完成底稿和规格检查。测试开关 NIUPPT_AUTO 只用于模拟。

## 修改现稿与分发

从用户现稿开始，保留未涉及页的版式、图表和内容；有 `deck.json` 时改 JSON 重新生成。对外发送时在 settings 加 `"public_output": true`，统一字体并清理元数据。
